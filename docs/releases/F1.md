## Current implementation slice

`resolvePolicy` accepts an explicit `businessDate` and candidate policy history; it returns a decision including `policyRowId`. It uses registered `POLICY_NOT_FOUND`/`POLICY_OVERLAP` errors. It is not connected to live transactions, so it does not yet ensure unresolved transactions enter `Q-POLICY_MISSING` or that aggregates retain the decision row. It has no policy cache. All test policies are synthetic and no principal-specific values were introduced.
