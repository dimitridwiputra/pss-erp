# ADR-0015 — Finance controls, shared approval handoff, reversal and summary scope

**Status:** Accepted, 30 September 2026. **Business decisions:** MVP-OD-7 through MVP-OD-10. This ADR clarifies ADR-0013 and DEC-109; it does not change domain ownership.

## Control accounts (MVP-OD-7)

Finance represents control status in its existing `Account` / `AccountRole` / `AccountRoleMapping` model, using explicit role metadata: `is_control_account`, `subledger_owner`, `manual_posting_policy` (`DENY`, `TEMPLATE_ONLY`, `ALLOW`), and `reconciliation_pair`. Account names and number prefixes are never classification rules. `AR_CONTROL`, `AP_CONTROL`, `GRNI`, `INVENTORY`, `INVENTORY_IN_TRANSIT`, `INVENTORY_IN_TRANSFER`, financially valued `INVENTORY_QUARANTINE`, `UNAPPLIED_RECEIPTS`, `CUSTOMER_DEPOSITS`, and `CASH_IN_TRANSIT` are control roles with `DENY`. A `MANUAL` or `ADJUSTMENT` journal touching one is rejected with `CONTROL_ACCOUNT_MANUAL_POSTING` at validation and submit, with a database guard at post. Only a SYSTEM journal from the owning domain's economic event may affect it. Opening balances use MIG-001, never the free-form manual journal. `BANK`, `CASH_ON_HAND`, and `PETTY_CASH` are not automatically controls; a workflow may configure `TEMPLATE_ONLY` separately.

## Approval (MVP-OD-8)

`platform.approval` alone owns the type registry, request, step, routing, thresholds, levels, expiry, delegation, SoD and decision audit. Type codes such as `journal`, `journal_reversal`, `credit_override`, `stock_adjustment`, `payment_reversal`, and `period_close` are registered centrally. An owner-domain transaction stages its subject, stores request correlation and subject version, and appends an approval submission to its transactional outbox. It does not call Platform over the network or write Platform tables. Platform's inbox creates the request and step, and its decision, audit, state transition and `APPROVAL_DECIDED` outbox commit in one Platform transaction. The owner-domain inbox checks request ID, type, subject reference, subject version and prior application, then performs its own mutation, audit and outbox in one transaction. Request submission is unique for `(type, subjectRef, subjectVersion)`; decision consumption is idempotent by event ID and request ID. Platform serializes concurrent decisions. The owner records effect lifecycle `PENDING`, `APPLIED`, `STALE`, or `FAILED` separately from Platform's decision. No distributed transaction or cross-domain table write is used.

## Reversal (MVP-OD-9)

For approved `MANUAL`, `ADJUSTMENT`, and eligible `OPENING` reversals, use the original accounting date when its period is OPEN. If CLOSED, default to the first valid date in the next/current OPEN period and set `latePosting=true`; a formally reopened original period can receive the reversal. A REVERSAL journal is separate, balanced, has opposite sides and identical dimensions, links both ways, requires a reason and `journal_reversal` approval, and has maker different from approver. No human role, including SYSTEM_ADMIN, may call `ReverseJournal` on a SYSTEM journal; return `SYSTEM_JOURNAL_REVERSAL_FORBIDDEN` and identify its source document. A SYSTEM correction arrives only as a registered compensating economic event from the original fact's owning domain. Finance verifies source reference, original economic posting, correction dedupe, effective posting rule and provenance, then posts a compensating SYSTEM journal using the event business date and ordinary period handling. Closed periods use the existing deferred-posting/reopen path; Finance users do not choose a SYSTEM reversal date.

## Gross-profit summary (MVP-OD-10)

`control_station.gross_profit_summary.view` is independent of Finance report permissions and `finance.branch_pnl_visible`. CEO and COO receive ORGANIZATION scope; BRANCH_MANAGER receives only assigned BRANCH scope. SALES_SUPERVISOR, SALES_ADMIN, SALES_REP, warehouse, driver, dispatcher and DATA_ANALYST have no default Control Station grant. The Finance API enforces branch scope in the query before returning posted Finance Net Sales, COGS, Gross Profit, Gross Margin %, and previous comparable period. The permission grants no full P&L, Balance Sheet, Cash Flow, Trial Balance, journal lines, GL drill-down, other-branch profit or Finance configuration. Branch Manager detailed P&L remains conditional on `finance.branch_pnl_visible=true` and its separate permission. Transaction-specific margin for price approval does not imply aggregate summary access.

## Architecture alignment

In `docs/ARCHITECTURE.md` §4.2, Finance's prior unqualified “approvals” bullet means Finance owns the business effect and subject state; the approval mechanism belongs only to Platform. Existing PRD language implying that Finance publishes `APPROVAL_REQUESTED` as a Platform event is superseded by the owner request outbox followed by Platform's factual `APPROVAL_REQUESTED` event. ADR-0013's single-command audit/outbox invariant applies independently inside each owner transaction.
